# LoRA Rank 容量对照

本页为历史 4,000 图容量对照；2026-10-05 完整训练集适配器和串行路由结果见[最新实验](EXPERIMENTS.md)。
## 研究问题与结论

保持数据、训练计划和生成设置一致，将语言侧 LoRA rank 从 2 增至 4、8，是否能改善血细胞八分类？

三组均已完成 8,000 步训练。r=4 的最佳开发集 macro-F1 为 97.0140%，r=2 为 96.9708%，r=8 为 96.6821%。r=2 与 r=4 接近，增加至 r=8 在本轮没有收益；保留 r=4 为默认容量点，同时把 r=2 作为更省参数的近似可行方案。

## 固定实验设置

| 项目 | 设置 |
|---|---|
| 数据 | BloodMNIST 224；官方 train 每类 500 张，共 4,000 张；官方 val 每类 50 张，共 400 张 |
| 初始化 | 同一 Qwen3.5-4B base，新建 LoRA；不加载历史适配器 |
| 作用层 | 语言侧 full-attention 层 3、7、11、15、19、23、27、31 的 q_proj / v_proj |
| 容量变量 | rank=2/4/8，alpha=4/8/16，固定 alpha/r=2 |
| 其余参数 | dropout=0.05，原始参数与视觉编码器冻结 |
| 优化 | seed=42，BF16，batch=1，AdamW，weight decay=0.01，gradient norm clip=1 |
| 训练计划 | 两轮 4,000 图，共 8,000 步；第 1–4,000 步 lr=2e-4，第 4,001–8,000 步 lr=5e-5，保留 AdamW 状态 |
| 选模 | 每 1,000 步评估固定开发集；macro-F1 优先，其次 accuracy，最后较早 step |
| 生成 | RGB，min pixels=65,536，max pixels=448²；greedy，thinking=false，max_new_tokens=32 |
| 输出解析 | 八类规范标签；其余计 invalid 且计错 |
| 运行设备 | 单张 NVIDIA RTX 3090 |

数据采样、类别顺序和指标定义与 [主实验协议](PROTOCOL.md)一致。三组评估仅使用开发集，不读取测试图像或标签。

## 最佳开发集结果

| Rank | Alpha | 可训练参数 | 最佳 step | 正确/总数 | Macro-F1 | Accuracy | Invalid |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 2 | 4 | 229,376 | 8,000 | 388/400 | 96.9708% | 97.00% | 0 |
| 4 | 8 | 458,752 | 5,000 | 388/400 | 97.0140% | 97.00% | 0 |
| 8 | 16 | 917,504 | 8,000 | 387/400 | 96.6821% | 96.75% | 0 |

r=2 与 r=4 都答对 388 张，错误的类别分布不同，因此 macro-F1 略有差异。两者差距只有 0.0432 个百分点；这次单 seed、400 图开发集实验适合说明参数容量的取舍，跨 seed 复验才有助于判断排序的稳定性。

## 与首页主结果的关系

首页的 r=4 模型来自“2,000 图试训 → 4,000 图热启动续训”，选定新增 step_03000；本轮 r=4 从 base 新建 LoRA，选定 step_05000。两者训练历史不同，是两个独立适配器。

本轮报告的是选模使用的开发集分数；首页的 94.68% accuracy / 94.01% macro-F1 是原主模型在官方测试集的分数。主实验指标与路由结果均保持原记录。
